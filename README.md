# Microprice

**Does order-flow imbalance predict short-horizon returns after costs?** A research and execution framework for market microstructure.

This is a research project, not a trading bot. We're testing whether order-flow imbalance (OFI) predicts 10–60s mid-price returns after controlling for spread, volatility and momentum, and after transaction costs. A clean negative result counts as a finding.

## Hypotheses

| ID | Hypothesis |
|----|------------|
| H1 | OFI predicts the sign and size of the next *h*-second mid-price return |
| H2 | OFI adds information beyond spread, volatility, momentum and top-of-book imbalance |
| H3 | Predictive power decays with horizon, fastest in liquid names |
| H4 | The signal is still profitable after realistic costs |
| H5 | The signal is regime-dependent and decays over time |

Full tests and methodology are in [QUANT_RESEARCH.md §1 and §4](./QUANT_RESEARCH.md).

## Interface contract (v1)

Change it only by agreement, and bump the version.

| Artifact | Producer → Consumer | Format |
|----------|---------------------|--------|
| `data/features/{symbol}/{date}.parquet` | QE → QR | `ts_ns`, `symbol`, one column per feature, labels `y_10s`, `y_30s`, `y_60s` |
| `data/signals/{run_id}.parquet` | QR → QE | `ts_ns`, `symbol`, `signal` (target position in [-1, 1]), `model_id` |
| `configs/strategy.yaml` | QR → QE | thresholds, holding period, max position, cost scenario |
| `results/{run_id}/` | QE → QR | `trades.parquet`, `pnl.parquet`, `metrics.json`, `config.yaml`, git SHA |

- `ts_ns` is the **local receive time**, int64 nanoseconds UTC. Exchange time is stored separately.
- Every result must be reproducible from `(git SHA, config, data version)`.
